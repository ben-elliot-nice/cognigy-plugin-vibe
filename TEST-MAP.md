**What this branch is.** A local-only merge of the exact remote head SHA of every open PR (#1–#16) into `main` (8812112, v1.12.0). The GitHub PRs are untouched. Companion docs:

- `VALIDATION-REPORT.md` — adversarially-verified review findings (Part A) + per-workflow usage guides (Part B). Read Part B before testing each area; it has the exact tool calls.
- `validation-detail.json` — raw per-PR validation/refutation data.
- "Merge decision log" below — every place I made an integration judgment call. **If a behaviour is wrong in an area listed there, suspect the merge first, then the PR.**

## Interaction matrix — where features must work in concert

These are the seams where "feature A and B don't work together" would show up. Each was hand-composed during the merge (see log), so they're both the highest-value holistic tests and the most likely merge-artefact sites:

1. **#16 + #6 + #11 (the node-write pipeline).** One `update` call now flows: `filePath` resolution (#16) → say/toolAnswer normalisation (#11) → conflict gate (#6) → PATCH → snapshot refresh (#6). Test the full chain in one call: push a code node from a file, edit in UI, push again from the file → must get `conflict: true`; `forceWrite: true` → must succeed AND refresh the snapshot (a third push with no UI edit must NOT conflict).
2. **#16 + #6 via `create`:** create a code node with `filePath`, then update it — the create-time snapshot (#6) must have recorded the FILE content, or the first update will false-positive.
3. **#12 + everything that writes.** With cache enabled, do a write then immediately read the same resource — must see fresh data. Especially: delete a flow → `list_resources`/name resolution must not resurrect it.
4. **#4 + #12 (my wiring).** Degraded boot then mid-session `cognigy-setup` with `COGNIGY_CACHE_ENABLED=true` — the cache must come up with the runtime (I moved CacheStore construction into `RuntimeManager.ensure()`; this exact path exists in no PR's own tests).
5. **#4 + #14.** Hot reload under degraded mode: `reload_mcp` then configure creds — runtime rebuild must still work after respawn.
6. **#13 + #14.** `explain` sits directly above `reload_mcp` in the dispatch switch — I restored a dropped `break` there (see log). Verify `explain {}` does NOT error about dev mode (that would mean fall-through into `reload_mcp`).
7. **#6/#31(main) gate stacking.** A first mutating node-write in a session can now be blocked twice for different reasons: main's backup gate, then #6's conflict gate. Confirm the error messages route you correctly through both (backup decline → conflict diff → forceWrite).
8. **#1 + #2 on VPN + CXone.** URL derivation and TLS trust both rewire the client's environment — boot on VPN against CXone and run one read + one `talk_to_agent`.

## Known defects you WILL hit (owned by PRs, not the merge)

- **#2 will not fix VPN TLS on your Mac.** The `/etc/ssl/cert.pem` probe short-circuits before the keychain branch, and the keychain branch queries `SystemRootCertificates` instead of `/Library/Keychains/System.keychain` where the NICE CAs actually live (verified on this machine). Needs rework before production.
- **#6's PR branch still contains the machine-specific `node_modules` symlink** — merge-blocker on the PR itself.
- **#12's cacheInvalidation tests fail on its own head** (backup-gate interaction). Reproduced at `af70b2d` directly. The fix used here (gate-priming retry) should be lifted onto the PR.
- **#3's skill docs contain wrong parameter names** (`resourceId` vs `id`, missing `raw: true`, missing `message`) — an agent following them verbatim will hit Zod errors.
- **No CI runs on any of these PRs** — "checks passed" was never true; this branch's local run is the first time the combined suite has been executed.
